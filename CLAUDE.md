This file is for whichever Claude session picks up this project next. It's the live personal portfolio site for Tom de Gay (senior product designer, Head of Design at Quantemplate), maintained directly in Claude Code.

**Read the Architecture and Conventions sections as current. Everything under "Session history" is a dated changelog** — useful for *why* a decision was made, but several of those notes describe an older structure (per-page CSS, per-page lightbox JS, a copy-pasted nav script) that has since been replaced by shared files.

## What this project is

A static, no-build personal site: home, about, contact, three "approach" pages (Learning from wayfinding, Design and AI, Design craft), and a case studies section with six long-form write-ups — four Quantemplate, plus Image Insight (a coaching tool) and Zonefully (a planning app). No framework, no bundler, no package.json: hand-authored HTML plus three shared files (`styles.css`, `nav.js`, `lightbox.js`), deployed to Vercel.

Repo: `https://github.com/tom-degay/tube-alloys.git` (renamed from `TDG-website` in Sept 2026 — GitHub redirects the old path permanently, so old clones keep working), local working copy still at `/Users/Tom/Github/TDG-website` on Tom's Mac.

## Architecture

- **Plain static HTML.** Every page is a single `.html` file, with no templating engine and no build step — what's in the file is what ships.
- **CSS lives in `/styles.css` plus a per-page `<style>` block.** Each page's `<head>` has `<link rel="stylesheet" href="/styles.css">` followed by a `<style>` block holding only that page's own rules. `styles.css` carries the `@font-face` declarations (root-absolute URLs) and the ~274 rules every page renders identically — nav, links, eyebrow/kicker, case blocks, figures, lightbox, TOC, animations. **The inline block always loads after `styles.css`, so a page rule beats a shared rule of equal specificity.** Two things to know when editing:
  - **Adding a rule to `styles.css` applies it to all fourteen pages**, including ones that never had it. Before hoisting anything, check that no other page has elements the selector would newly match.
  - **A rule is only in `styles.css` if every page that had it had it identically.** Deliberate per-page divergence (e.g. the pages that set `html { scroll-padding-top }`) is preserved inline on purpose — don't "tidy" it into the shared file without asking, that's a design decision.
  - Rules that had to stay inline for cascade reasons are marked in the migration commit; the lightbox, `.ui-video`, `.head-fade` and `.figure img` sets are inline on every page because the pages order them differently.
- **Every `<img>` carries its intrinsic `width`/`height`, and `styles.css` has `img { height: auto }`.** The attributes let the browser reserve the right box before the file arrives. **Keep that `height: auto` rule** — HTML `width`/`height` are presentational hints for the width and height *properties*, not merely an aspect ratio, so without it the attribute's height wins wherever CSS sets a width and leaves height alone. That squashes the image and silently defeats `aspect-ratio` (it only applies when a dimension is `auto`). When adding an image: read its real pixel size (`sips -g pixelWidth -g pixelHeight`) — a guessed ratio moves the layout instead of stabilising it. Images whose `src` is swapped at runtime (the `#lightbox` `<img>`, `.gallery-main`, `.gallery-fade`) deliberately have **no** dimensions.
- **`loading="lazy"` goes on images below the fold only.** Anything in the first screen at 1400×900 or 375×812 stays eager, as do the nav icons (lazy there would pop on first hover). Six side-rail `.related-thumb` images on wayfinding/ai/design-craft are lazy despite sitting above the fold at ≥1100px — pre-existing, harmless in practice, flagged rather than changed.
- **The lightbox is one shared file: `/lightbox.js`.** Loaded with `<script src="/lightbox.js" defer></script>` by the nine pages that have a `#lightbox` (wayfinding, ai, design-craft, the six case studies). It handles all three content sources — standalone `.figure img` (one page-wide list), each `.gallery` (its own list), and `.ui-video-expand` (video in the same modal) — plus swipe, keyboard, focus trap, and the `.is-tight` close-button fallback. It replaced six drifted per-page copies. Two conventions:
  - **Captions are set with `innerHTML`**, sourced from `figcaption.innerHTML` or a `data-caption` attribute, so a caption can carry a link. Both sources are our own markup; never feed it anything untrusted.
  - **A `.ui-video` marked `data-hover-controls` reveals the native player controls on hover** (pointer devices only, via a `(hover: hover) and (pointer: fine)` check — touch devices never attach the listener, so controls never appear on mobile no matter what), inline *and* in the lightbox. Every `.ui-video` on the site carries it now (added to all sixteen, Sept 2026 — originally only `validation.html`'s drill-down video had it). Mark the markup on any new `.ui-video` — don't re-add a filename check in the script.
  - **Never set `aria-label` on a figure image.** It overrides the `alt`, so every screenshot on a page announces as the same thing. The alt IS the accessible name; `makeOpenable` only supplies a label for images that have no alt to lend.
  - **Gallery selection is guarded by a sequence token.** Caption, counter and active thumb update synchronously but the image waits on a preload, so two quick clicks can finish out of order. A preload that is no longer current is discarded — keep that check.
- **The nav's behaviour is one shared file: `/nav.js`**, loaded with `<script src="/nav.js" defer></script>` by all fourteen pages. It holds the mobile hamburger (toggling `.site-nav.is-open` below 640px) and the two desktop popovers. Note the popover handler deliberately returns early below 640px, where the dropdown is shown expanded inline and the link should just navigate. On desktop the trigger deliberately does **not** navigate, so `nav.js` gives it `aria-haspopup`/`aria-expanded` rather than letting it announce as a plain link.
  - **Escape needs `.is-dismissed`, not just `.is-open`.** The panel is revealed by `:hover` and `:focus-within` too, which CSS keeps matching after JS drops `is-open` — so Escape alone looks broken while the pointer rests on the item. `dismissAll()` blurs focus and adds `.is-dismissed`, which a desktop-only rule in `styles.css` uses to force the panel hidden until the pointer or focus leaves.
- **No shared partials for markup.** The nav's CSS is in `styles.css` and its behaviour in `nav.js`, but its *markup* (`<nav class="site-nav">`) is still copy-pasted identically into every page's `<body>`. **Any change to the nav's markup or links must be manually applied to all fourteen live pages** (styling goes in `styles.css` once, behaviour in `nav.js` once). Markup is now the only thing still duplicated, and it remains the main drift risk — there is no include mechanism. Do markup changes with a throwaway Python script over the file list rather than fourteen hand-edits.
- **Hosting: Vercel**, configured via `vercel.json`:
  ```json
  { "cleanUrls": true, "trailingSlash": false }
  ```
  This is why internal links are extensionless (`href="/about"` resolves to `about.html`). Keep this in mind when adding new pages — they'll be reachable at `/<filename-without-extension>`.
- **Every committed file in the repo root is served as a static asset — including this one.** `CLAUDE.md` was live at `https://tomdegay.com/CLAUDE.md` (200, 75KB) until Sept 2026, publishing the repo URL, the whole dated session history below, Tom's local filesystem path and the source Google Doc IDs. Nothing linked to it, but `/CLAUDE.md` is a well-known path and `robots.txt` allows every crawler. **`.vercelignore` at the repo root now excludes `CLAUDE.md` and `AGENTS.md` from the deployment — keep it.** Note `cleanUrls` does not hide anything: `/CLAUDE` 404s but `/CLAUDE.md` served fine. Before committing any new non-page file to the root (notes, scratch HTML, a data dump), either add it to `.vercelignore` or check it is something you would publish, and verify with `curl -o /dev/null -w '%{http_code}' https://tomdegay.com/<file>` after the deploy.
- **Fonts:** "Fakt Blond SemiBold" self-hosted (`FaktProSemiBold.woff2`/`.woff`, `@font-face` declared per-page) used for all display/heading text via the `.display` class. Body/UI text falls back to the system font stack. "IBM Plex Mono" is pulled from Google Fonts and used for small overline/label text (the `.eyebrow`/`.kicker` pattern, see below).
- **Contact form** (`contact.html`) submits client-side via `fetch` to `https://api.web3forms.com/submit` using a Web3Forms public access key embedded in the form (`access_key` hidden input) — this is a public/publishable key by design for that service, not a leaked secret. The form also carries a real `action`/`method` so it still posts without JS. The request has a 15s `AbortController` timeout, and **every** failure path shows the same LinkedIn fallback — there is deliberately no email address on the site, so never write a message that tells people to email him.
- **`index.html` has its own desktop layout, and it is the one page that diverges structurally.** Above 1024px the landing page is re-gridded into a wide editorial band, and the case-study cards go horizontal from 800px -- lower, so the two-up card grid never appears. Below 800px every width renders exactly as it always did. It lives in `index.html`'s inline `<style>`, in two blocks (`min-width: 1024px` for the layout and `min-width: 800px` for the cards, the card one placed second so it beats the 820px two-up rule) plus a handful of base rules — **nothing went into `styles.css`**, so the other twelve pages are untouched. See "Landing page desktop layout" under the design-system section for the grid itself. Two consequences worth knowing before editing that page:
  - **`main` is no longer the 900/1080 column there.** It is `max-width: 1500px` with a shared `--gutter`, and `.site-nav-inner` is overridden to match so the brand, the section labels, the hairlines and the card grids all start on one vertical line. Change one and you must change the other or the whole page goes out of alignment.
  - **`html, body { overflow-x: clip }` is load-bearing on that page.** The hero video deliberately runs off the right of the window, and this is what clips it. It has to be *both* elements (the root's overflow propagates to the viewport, so `body` alone is ignored) and it has to be `clip`, not `hidden` — `hidden` makes `body` a scroll container and the sticky nav scrolls away with the page. Both were measured; every other combination either still scrolled sideways or broke the nav.
- **No JS framework or dependencies.** Two shared files (`/nav.js`, `/lightbox.js`) plus per-page inline `<script>` blocks for things only that page does: the contact form's submit handler (`contact.html`), the TOC scroll-spy (the six case studies + wayfinding + ai + design-craft), the pre-paint animation arming and word-by-word entrance, the stats counter (`pipelines.html`), and the case-icon/card reveal animations. A GoatCounter analytics tag sits near `</body>` on every page except `about.html`.

## Visual design system / conventions

The site is a dark theme: `color-scheme: dark`, `background: #000` on `html, body`, white text at varying opacity for hierarchy. When adding UI, match these existing conventions rather than inventing new values:

- **Text hierarchy via white opacity**, not different hues: `#fff` for primary/loudest text (headings, brand), `rgba(255,255,255,0.68)` for secondary body copy (`.job-desc`, subtitles), `rgba(255,255,255,0.45)` for muted labels/keywords, `rgba(255,255,255,0.35)` down to `rgba(255,255,255,0.12)` for borders/dividers at decreasing emphasis.
- **Link underline pattern**, defined once in `styles.css` (the base `a` rule and all its `:hover` / `[target="_blank"]` companions live there):
  ```css
  a {
    color: #fff;
    text-decoration: none;
    border-bottom: 1px solid rgba(255, 255, 255, 0.22); /* all fourteen pages */
    padding-bottom: 1px;
    transition: border-color 0.15s ease, opacity 0.15s ease;
  }
  a:hover, a:focus-visible {
    border-color: rgba(255, 255, 255, 0.9);
  }
  ```
  External links (`a[target="_blank"]`) get an animated `→` arrow via `::after`.
  **Known footgun:** any scoped rule like `.some-class a { border-bottom-color: ...; }` that doesn't also define its own `.some-class a:hover`/`:focus-visible` override will tie in CSS specificity with the global `a:hover` rule (both are exactly one class/pseudo-class + one type selector) and — because it's declared later in the file — will permanently win, silently killing the hover effect for links in that scope. This exact bug existed in `.about-copy a` in `about.html` and was fixed this session (see below). If you add a new scoped link style, always pair it with its own `:hover`/`:focus-visible` rule.

  **A sibling footgun, same family:** an *inherited* value always loses to an *explicit* rule on the element itself, no matter how the two selectors compare on specificity. `.principle blockquote` sets `color: #fff`, meant to cover its text — but a multi-line blockquote is built as `<blockquote><p>…</p><p>…</p></blockquote>` (see `.principle blockquote p + p` below), and `.principle p { color: rgba(255,255,255,0.82) }` is a direct, explicit rule on those `<p>` tags, so it won regardless of the blockquote's own color. Fixed with `.principle blockquote p { color: inherit; }` in `styles.css` (more specific than `.principle p` too, so it wins on both counts, not by luck). A single-text-node blockquote (no nested `<p>`, e.g. the "Designing for AI" framing questions) was never affected — inheritance only fails to apply once something *else* sets the property explicitly on a descendant.
- **"Eyebrow"/"kicker" overline label style** (used for small caps section labels like "About", "Principal Experience", "Case Studies", and for case study kickers/keywords): IBM Plex Mono, 14px, weight 500, letter-spacing 2px, word-spacing -3px, uppercase, color `#00d8aa` (teal) for the eyebrow itself, `rgba(255,255,255,0.45)` for the muted keyword-list variant. Keyword lists use a middle-dot `·` separator (e.g. "Product strategy · Systems thinking · Process design") — a pipe `|` was used inconsistently in older markup but has been normalized to `·` everywhere as of this session.
- **Section dividers:** `<hr class="rule">` — `border: none; border-top: 1px solid rgba(255,255,255,0.2); margin: clamp(32px,5vw,48px) 0;`. Used between major page sections. **This rule is declared inline, per page — it is not in `styles.css`** (only a `:has()` variant, for the back-to-top spacing case, lives there). Every page must carry its own copy or a `<hr class="rule">` (including the one `footer.js` injects) silently falls back to the browser's default `<hr>`: a `2px` grey `inset` border with an `~8px` margin, reading visibly heavier and sitting much closer to the content than the rest of the site. `about.html` was missing it until this session — check any new page has one.
- **Site nav** (`.site-nav`): `position: sticky; top: 0; z-index: 50;`. The translucent blurred background (`rgba(0,0,0,0.86)` + `backdrop-filter: blur(10px)`) lives on **`.site-nav::before`** (absolute, `inset:0`, `z-index:-1`), *not* on `.site-nav` itself — putting `backdrop-filter` on `.site-nav` makes it a "backdrop-filter root" that traps the mobile menu panel's own `backdrop-filter` so the panel can't blur the page. Keep the frost on the pseudo. It intentionally has **no** `border-bottom` (see below) — don't re-add one without being asked. Links: About / Approach (a `.nav-item` popover → Design and AI, Design Craft, Learning from wayfinding) / Case Studies (a `.nav-item` popover to the six case studies) / Contact. **There are now two `.nav-item` popovers in the nav, not one** — any nav edit must keep both in sync across all fourteen pages.
  - **Dropdown cards** (`.nav-dropdown-card`): a white `.nav-dropdown-card-title` (the full page/study title), optionally preceded by a green `.nav-dropdown-card-kicker` mono overline. **The kicker is on the Case Studies dropdown only** — the Approach dropdown is title-only (Tom: on the Approach popover "we don't need a double level heading"). So `.nav-dropdown-card-kicker` CSS lives in every page but only the 6 Case Studies cards render a span.
  - **Case Studies dropdown order matches the home-page / `/case-studies` card grid**: Pipelines · Column mapping · Feeds · Validation · Image Insight · Zonefully (kicker / title): Bringing clarity to complex data flows / Mapping inconsistent schemas at scale / Connecting organisations through data / Closing the loop on data quality / Making space for deeper reflection / Connecting long-term goals to everyday routines. Reorder any time the home grid is reordered.
  - Titles are plain text with **no `<br>`** — panel `min-width: 360px` so they sit on one line where they fit. **No current-page highlight** in the dropdowns; titles are always white (detail pages still carry a vestigial `is-current` class on their own card, no CSS acts on it). There is no `.nav-dropdown-card-subtitle` — the rule was deleted once nothing rendered one.
- **Mobile nav (≤640px):** the nav links collapse behind a `.nav-toggle` hamburger button. The `.site-nav-links` list becomes an absolutely-positioned panel below the bar (`display:none` → `display:flex` when `.site-nav.is-open`) with the same frosted `rgba(0,0,0,0.86)` + `backdrop-filter: blur(10px)` as the bar, and the Case Studies dropdown shown inline/expanded. Note the media query also has to re-null `.nav-item:hover/:focus-within .nav-dropdown { transform: none }` — the desktop centring rule (`translate(-50%, …)`) is more specific than the mobile `.nav-dropdown { transform: none }` and otherwise slides the open sub-list off-screen on tap. It **also must set `.site-nav-links { flex-wrap: nowrap }`** — the base rule is `flex-wrap: wrap`, so once the (now 6-card) dropdown made the open menu taller than the panel's `max-height` (`80vh`), iOS Safari wrapped the column into two side-by-side columns instead of scrolling. `-webkit-overflow-scrolling: touch` is on the panel for momentum scroll. The bars animate hamburger→X on an overshoot cubic-bezier ("bounce"); the middle bar is hidden with **both** `opacity: 0` **and** `transform: scaleX(0)` (on its own plain-ease transition, `.nav-toggle-bar:nth-child(2)`) — Safari was leaving the middle bar painted with `opacity: 0` alone while the siblings composited, so it needs the geometric collapse too. The toggle behaviour lives in `/nav.js` (shared). The `.nav-toggle` markup is still per-page; the mobile CSS is in `styles.css`.
- **Anchor scroll offset:** every page with in-page `#hash` links (the six case study detail pages + `wayfinding.html` + `ai.html` + `design-craft.html`, all of which have a `<nav class="toc">`) sets `html { scroll-padding-top: 100px; }` right after the `html, body` rule so jumped-to headings land ~44px below the sticky nav instead of behind it. Put it on the scroll container (`html`), not on the target elements — an earlier attempt used `.principle { scroll-margin-top }` on the wayfinding page but the ids live on the child `h2.principle-title`, so it was a no-op. **Any new page with a section TOC or hash links needs this rule.** `index.html` gained it when about.html's "People say" link started pointing at `/#testimonials-heading` — a page only needs it once something links into it by hash.
- **The case-study TOC deliberately stops at "Outcome"** — the trailing "Resources" section (a short list of external links) exists on `column-mapping.html`, `feeds.html`, `validation.html` and `image-insight.html` but is not one of the `<nav class="toc">` links or tracked by the scroll-spy (Sept 2026; `pipelines.html` and `zonefully.html` never had a Resources entry). This falls out of the scroll-spy's own design rather than needing special-casing: it only observes `<section>`s that have a TOC link (built from `document.querySelectorAll(".toc a")`), and the observer callback only ever *sets* a new `.is-active` link when an observed section starts intersecting — it never clears one when a section stops intersecting. So once the page scrolls past Outcome's section into the untracked Resources section, nothing fires, and "Outcome" simply stays highlighted for the rest of the scroll. Verified with a stepped scroll (30 increments, each awaited past a rendered frame) — a single instant jump to `scrollHeight` is **not** a valid test here, since IntersectionObserver only evaluates intersection at rendered frames and an uninterrupted jump skips every section's transient state along the way, including Outcome's own activation.
- **Figure strips** (`<figure class="figure figure-strip">` → `.figure-strip-imgs` → N images + one shared `figcaption`): a row of images that each open the lightbox, every cell forced to `aspect-ratio: 4/3; object-fit: cover`. **The column count is a per-page inline default** (3 on `pipelines.html`, 2 on `validation.html`) **overridden by a modifier class in `styles.css`**: currently just `.figure-strip-4` for four across (`pipelines.html`'s code-editor strip). A `.figure-strip-2` for a 2×2 existed briefly and was deleted once nothing used it — re-add it the same way if a two-column strip is ever wanted. The modifiers are two-class selectors so they beat the pages' single-class default whatever the source order; keep them that way. **A portrait image in a 4/3 cover cell keeps only a horizontal band, centred by default** — if that crop lands on empty space, either re-crop the source to 4/3 so nothing is cut at all (what `code-editor-2.png` does — it was a 832×1040 portrait, trimmed to 832×624), or add a targeted `object-position` rule beside the existing `img[src$="validation-operation.png"]` one in `styles.css`. Prefer the re-crop: it fixes the lightbox too, where `object-fit` does not apply.
- **Case blocks** (`.case-block`, used on the home page preview, the case studies index, and each detail page's "Next case study" block): bordered rounded cards with a hover lift (`transform: translateY(-4px)`, brightened border, background tint) and an arrow that translates on hover. There was an `.is-soon` variant for not-yet-published studies; every study is live now, so that CSS has been deleted — reinstate it if a placeholder card is ever needed again. The lift used to be `scale(1.02)`, but a centred scale grew the card past the page's left/right alignment edges — looked like the card jumped sideways; `translateY` avoids that. The `.has-image` variant additionally zooms its image (`transform: scale(1.03)` on `.case-block-media`, inside `overflow: hidden`).
  - **Inside `.case-block-text`**, in order: `.case-block-kicker` (green `#00d8aa` IBM Plex Mono, uppercase — a short project label: **COLUMN MAPPING / FEEDS / VALIDATION / PIPELINES / IMAGE INSIGHT / ZONEFULLY**, all now live studies, written sentence-case in the HTML and uppercased by CSS), then `.case-block-title`, `.case-block-subtitle`, and `.case-block-keywords` (muted grey mono keyword list). `.case-block-soon-label` and `.case-block.is-soon` have been deleted — no coming-soon cards left. The `.case-block-kicker` rule is duplicated into every file that renders a card (`index.html`, `case-studies/index.html`, and each detail page's "Next case study" block) — keep in sync like the nav.
  - **The kicker's study icon exists twice in each landing-page card**: the flat `<img class="case-block-kicker-icon">` used everywhere, and the inline stroke-draw `<svg class="case-icon">` lifted from the top of that study's own page, shown only above 800px with the flat one hidden. They are **different drawings, not the same file animated** — feeds is four animated paths against one flat — and the animated one carries about half the stroke weight, being set for a 42px render, which reads faint at the 14px the narrow cards use. Hence the swap in CSS rather than in the markup. `.case-icon` and `.case-icon-trace` live in `styles.css`, but **`@keyframes case-icon-draw` is defined per page**, so any page using them needs its own copy. On the landing page the draw is held with `animation-play-state: paused` until the card picks up `.is-revealed` from the existing reveal observer, so it is not spent below the fold; pausing rather than delaying keeps each trace's own stagger.
- **"Approach"** — a section on **`index.html` only** (removed from `case-studies/index.html`), sitting **between Case Studies and Other work** (its own `<hr class="rule">` either side), `<section aria-labelledby="approach-heading">`. Three `.case-block has-image` links — Design and AI → `/ai`, Design craft → `/design-craft`, Wayfinding → `/wayfinding` (**title + subtitle only, no green kicker**) — in a **`.case-blocks approach-blocks`** grid: `repeat(3, 1fr)` at `@media (min-width:820px)` (side-by-side row), 1-col below.   - **To downscale a PNG and keep it a PNG, use `ffmpeg`, not `sips`** — the problem is the encoder, not the resize, so PNG→PNG is fine with a better one:
    ```
    ffmpeg -y -i IN.png -vf scale=2000:-1:flags=lanczos -compression_level 100 -pred mixed OUT.png
    ```
    Measured on the two Pipelines code-editor shots (Sept 2026): `code-editor-3.png` 2880px/1.9 MB → 2000px, **868 KB** with ffmpeg but 1.0 MB with `sips -Z`; `pipelines-today.png` 3024px/496 KB → **404 KB** vs 448 KB. UI text stayed fully legible at 2000px. Check the result is actually smaller before keeping it, and update the `width`/`height` attributes to the new size.
  - **A screenshot wider than ~2000px is oversized** whatever its format — nothing on the site is displayed above ~340px outside the lightbox, and the lightbox caps at the viewport. Downscaling is a resolution change, not a format change, so it does **not** conflict with "if Tom supplies a PNG, keep it a PNG" — that rule is about not turning a sharp-text screenshot into JPEG. Still flag it rather than doing it silently.
- **Claude cannot save a pasted image to disk in the desktop app** — pasted images arrive only as vision input, and this client doesn't stage them to a temp path. Ask Tom to save the asset himself (an `osascript` clipboard-to-file one-liner, or Finder) into `case-studies/media/`, then wire up the markup. Rename anything with spaces or a version suffix (`… v3.png`) to kebab-case — no tracked media has a space or a capital in its name.

### Deploy flow

Tom says "push to prod" and changes go **straight to `main`**, not through PRs. Use `git push origin HEAD:main` when the local commit is a clean fast-forward, otherwise commit on `main` then `git pull --rebase origin main && git push`. **Wait for the deploy and verify against the live host** — a new shared file (`styles.css`, `nav.js`, `lightbox.js`) 404s for the first few seconds, and every page depends on it. **Six verification traps, every one of which produced a passing test that
proved nothing.** The existing advice in the de-duplication note below still
stands; these are additions:

1. **`scroll-behavior: smooth` is set in `styles.css`.** Any assertion that
   scrolls and then measures reads the *pre-animation* position and passes.
   This produced a confident, wrong conclusion about which `overflow-x` rule
   fixed the hero bleed. Use `behavior: 'instant'`.
2. **On SVG elements `className` is an `SVGAnimatedString`**, so
   `.className.toString()` returns `"[object SVGAnimatedString]"`. A DOM-wide
   geometry comparison that keys on it silently misaligns the moment one side
   has an extra inline SVG. Use `getAttribute('class')`.
3. **IntersectionObserver never fires in an off-screen iframe.** The usual
   harness (`position: fixed; left: -10000px`) can't test anything gated on
   `.is-revealed` — the state stays exactly as it looks when broken. Drive the
   real page for those.
4. **Pixel-diffing this page is useless.** The hero video autoplays and the
   card vectors animate, so every capture differs — including a control of the
   page against itself. Compare geometry, or `getScreenCTM()` for SVG scaling.

5. **A deploy check is only as good as its marker.** Polling the live site for
   the word `stagger` returned LIVE on the first attempt, before the deploy
   could have finished — the word was already in two unrelated comments.
   Poll for something the change actually introduced.
6. **The fix can be worse than the bug, silently.** Overlapping the Union
   icon's bar and U as two subpaths of one path removed the Safari seam and

   ways and `fill-rule: nonzero` cancelled the overlap. Rasterising the

   not have, since Chrome never showed the original seam either.

**What is worth copying is the verification, because it repeatedly caught real
bugs that eyeballing would have shipped:** serve the pre-change pages alongside
the new ones (`git show HEAD:page.html > page.baseline.html`) and compare, per
element, both the computed styles and the *ordered list of CSS rules that match*
— the latter is state- and media-independent, so it covers `:hover`, open menus
and inactive media queries. Then drive the actual interactions and diff the
observable values.

Four traps that cost real time, all worth remembering:

1. **A harness that reports "identical" may be testing nothing.** One popover
   check passed while a synthetic click had navigated the iframe out from under
   it; one lightbox comparison passed because the baselines had been captured
   *after* the change. Sanity-check that the assertions can actually fail.
2. **Matching selectors against the live DOM misses script-toggled classes.**
   `.head-play`, `.is-open`, `.is-tight` match nothing at load, so rules using
   them look dead. Neutralise those classes before testing, or you will both
   leak rules onto pages that never had them and miss real order inversions.
3. **Parsers that ignore `@media` miss whatever is inside it.** This bit the CSS
   extraction and again the dead-rule sweep.
4. **A warm cache hides lazy-loading**, and mid-animation snapshots produce
   differences that look like regressions. Use a control run to tell an artifact
   from a real change.
